## Scope and production baseline

One new website quote submission should produce one **unsent ServiceM8 quote** in `X-New Website Quotes`. Use the submitted name, mobile, email and install address in the appropriate ServiceM8 fields. Copy all supplied project answers into the job description, organised under readable headings. Download linked Cooltech photos and upload them as actual ServiceM8 quote attachments, keeping the labelled source links in internal notes. Carry over files attached directly to the email as well, including when both formats arrive together. No pricing, sending, scheduling, or historical imports by default.

## 2. Build separately and test

1. Build a separate unpublished n8n workflow with a manual fixture/dry-run path and an activation cutoff. Dry-run performs classification, mapping and reconciliation reporting only: no conversion, record creation, note writes, attachment writes or inbox-state changes. Use Switch nodes for routing. Validate the node configuration and full graph, and save the workflow source and configuration reference in Git without credentials or customer data.
2. Process messages one at a time with durable progress keyed by the source inbox UUID. Check for manual conversion and previous processing immediately before writes. Verify overlapping runs cannot claim the same message. Store or recover the quote UUID before continuing with contact, description, notes and files. On a timeout after creation, reconcile against the inbox link or another verified correlation mechanism before retrying; **never blindly create again**. If outcome cannot be proven, send the item to manual review. Resume only missing steps on retry and verify final quote status, routing and expected files before marking complete.
3. Test against fixtures, then with isolated ServiceM8 writes if available. Cover link-only, files-only, both, no photo, multiple files, split/ducted variants, blank fields, malformed messages, unrelated inbox traffic, existing/ambiguous clients, replies, manually handled items, repeat polls, overlapping runs, inbox bursts, rate limits, and failures during quote creation, notes and uploads. Simulate a successful create whose response is lost and confirm that replay does not create another quote.
4. Acceptance: One submission produces one correctly routed, unsent quote; the known client/site data and supplied answers survive; notes are internal; the three linked photos in the test submission each open as actual quote attachments with descriptive labels. Direct email attachments also open on the quote, with no duplicate if the same file arrives both ways. Replays must not duplicate attachments. Test unavailable links, redirects, invalid image bytes, oversized files and partial transfer. No unrelated or legacy message is changed. Failures remain visible and recoverable without repeated writes or silent skips.

## 3. Pilot, cut over and roll back

1. Run a read-only comparison of what the new workflow *would* process against known quote traffic and the live job workflow's match rules. Record the production baseline and agree an activation timestamp, a pilot window and an owner. Older emails remain manual unless separately approved for backfill.
2. After approval, allowlist a single clearly identified test message for any production pilot. Do not run the existing schedule manually. Verify the quote in the UI, its source inbox state, the diary, files, and lack of unexpected notifications. Agree test record cleanup ahead of time. Get sign-off before enabling normal scheduled processing.
3. Monitor the first live batches and reconcile matching inbox messages to quote records through the first business day. Check for duplicates, omissions, wrong queues/statuses, incomplete attachments, errors/throttling, and any change in the existing job workflow's health. Have staff continue the normal manual path for exceptions, checking for an existing quote first.
4. **Rollback triggers:** duplicate/missing quotes, unexpected notifications, wrong routing, inbox-state changes outside the agreed path, or impact on the existing workflow. Disable only `COOLTECH_Website_to_Quote`; identify and safely stop any in-flight runs still capable of writing. Preserve the source-to-quote log and reconcile partial or already-converted messages before manual processing resumes. Leave the original workflow active. Do not bulk replay, delete or modify live records as part of rollback without separate approval.
